# XBot HarnessBench 评估报告（2026-08-12）

## 摘要

本报告沿用 `report_20260810.md` 的指标口径，做两件事：

1. **重新基线化**：将历史各阶段结果（原始基线、XBot old、XBot 当前、OpenCode
   对照）统一去除 `008-image-recognize` 和 `013-image-edit` 两个多模态任务后，
   按 104 个任务重新统计与配对对比。这两个任务已在 commit `4d52b46`
   （`eval: remove multi-modal cases`）中从评估任务集移除，因此 104 任务口径
   与当前代码库的任务集一致。
2. **新增 269aa3 两个全量 run 的分析**：`harnessbench-xbot-m3-269aa3`
   （Minimax-M3）与 `harnessbench-xbot-deepseek-269aa3`（deepseek-v4-flash），
   均为 commit `269aa3e`（tracked tree clean）上的单次完整 106 任务运行，另附
   与历史“稳定点”`harnessbench-xbot-m3-26f346`（commit `10d9f558`）的配对对比。

去除两个多模态任务后，104 任务口径的总体结果：

| 指标 | 原始基线 | XBot old | 稳定点 | OpenCode | M3 269aa3 | DeepSeek 269aa3 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

| 中位数 | 0.8268 | **0.9101** | 0.8462 | 0.8687 | 0.8834 | 0.9052 |
| 满分任务 | 23 | **35** | 33 | 27 | 30 | 37 |
| 零分任务 | 0 | 0 | 0 | 0 | 0 | 0 |

新结论：

- **269aa3 相对稳定点不降反升**。M3 配对均值差 **+0.0173**（30 胜 / 28 负），
  DeepSeek 配对均值差 **+0.0236**（31 胜 / 23 负）。两个近似 95% 区间
  （M3 `[-0.0083, +0.0429]`、DeepSeek `[-0.0010, +0.0483]`）仍跨过零点，但
  DeepSeek 的区间几乎不覆盖负值，是所有 XBot 对比中方向最强的一次。
- **非多模态口径下两个 provider 接近并列**。M3 对 DeepSeek 配对差
  **-0.0063**，区间 `[-0.0328, +0.0202]`。DeepSeek 中位数（0.9052）和满分数
  （37）更高；原 106 口径中 M3 的领先优势完全来自 `008`（1.0 vs 0.0）和
  `013`（1.0 vs 0.4）两个图像任务。
- **DeepSeek 明显更高效**：每任务 token 约 146k、模型调用约 9.75 次，约为 M3
  （238k、16.14 次）的六成；工具失败率两者接近（2.48% vs 2.37%），均低于稳定点
  的 3.02%，也低于 OpenCode 之外的任何历史 XBot 结果。
- 稳定点报告列出的主要回归任务（`078`、`084`、`048`、`073`、`041`）在 269aa3
  中被大部分修复，但修复分布不均匀：`078`、`048` 只有 M3 修好，`041`、`045`
  只有 DeepSeek 修好。

本报告是工程诊断，不是严格受控基准。两个新 run 是单次完整运行（未做分段合并），
但仅有一次观测；`008`、`013` 两个图像 sample 在两次新 run 中均只归档了单条
消息（模型实际运行约 15 轮并消耗大量 token），transcript 与 ACP 事件缺失，评分
基于工作区产物仍然有效，但不可审计轨迹。

## 结论

1. **269aa3 提交使 XBot 相对稳定点（10d9f558）不降反升**。M3 与 DeepSeek 的
   配对均值差分别 +0.0173 与 +0.0236，稳定点报告列出的主要回归任务（`078`、
   `084`、`048`、`073`、`041`）多数被修复；JobRegistry 重构没有引入可观测的
   质量回退。
2. **非多模态口径下 provider 选择不再是质量瓶颈**。去除 `008`、`013` 后 M3 与
   DeepSeek 配对差仅 -0.0063；DeepSeek 中位数与满分数更高，且每任务 token 与
   模型调用约为 M3 的六成。若评估继续排除多模态任务，DeepSeek 是更划算的选项。
3. **单次运行仍不足以定性 provider 或回归**。`078`、`048`（M3 优）与 `041`、
   `045`（DeepSeek 优）的分歧超过 0.3，M3 新增回归（`070`、`052`、`032`、
   `072`）在 DeepSeek 上并不存在。任何“改 prompt / 改工具就能复现”的结论都必须
   先经 multi-epoch 确认。
4. **效率差异集中在执行纪律而非输出**。DeepSeek 用更少的轮次和更短的上下文达到
   相近质量，但输出 token 并不少于 M3；OpenCode 的 0.65% 工具失败率仍是 XBot
   未触及的基准。工具失败率从稳定点 3.02% 降至 2.4% 左右，方向正确。
5. **证据局限已明确记录**：两个图像 sample 的 transcript 缺失；所有新结论均来自
   单次观测；OpenCode 对照仍是主机运行，环境不一致。

## 下一轮建议

1. 对 M3 与 DeepSeek 的 8-12 个分歧任务（`078`、`048`、`041`、`045`、`070`、
   `052`、`032`、`072`、`090`、`103`）各跑 3 epochs，区分模型随机性与框架差异。
2. 以 DeepSeek 为默认评估 provider 重跑基线对照（104 任务），若中位数与满分
   优势在多 epoch 下保持，可将效率收益并入正式报告。
3. 修复图像类 sample 的 transcript 归档（消息与 ACP 事件未落盘），避免未来
   resume 或审计时丢失轨迹；已移除多模态任务的情况下此项优先级可降低。
4. 在 DeepSeek 上复测 `041`、`045`、`077`、`080` 的执行路径，确认这些改善不是
   偶然高分；`078` 与 `048` 上 M3 的稳定满分也值得阅读 transcript 归纳可复用
   的规划模式。
